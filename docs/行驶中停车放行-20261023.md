# 平整直道的停车/放行实跑

上一轮连续巡线日志已完整保存：1792742773230-23287。无需因重新联网重复跑。

本轮只验证已识别的红色 stop 牌能否在运动中让车实际停下、拿走红牌能否保持等待，以及绿色 flow 牌能否恢复运动。不在坡面或凸起位置测试。

## 启动

只需上传新增的 `run_signal_motion_20261023.sh` 到 `/root/track-trial-20261010/bin`。沿用刚跑通的 `trackview_race_continuous_20261023`，不替换程序、原配置或模型。

```bash
cd /root/track-trial-20261010/bin
bash ./run_signal_motion_20261023.sh drive
```

默认 MANUAL，四项速度上限仍是 0.10 m/s；没有两秒定时退出。本轮仅在独立的比赛配置副本中将 `stopAfterCross` 设为 false，停车不依赖斑马线。原 `race.json`、`trackview.json` 不修改。

## 操作及反馈

1. 准备一段平整直道，前方留出至少约 1 米空地并有车旁断电手段。让车沿道路前进，牌子摆在道路外侧，不能成为车前障碍物，也不要盖住赛道边线。
2. 备好之前已经确认能识别为 stop 的红牌和 flow 的绿牌。红牌可从车前约 0.5–1 米处的赛道外侧开始尝试，牌面朝向摄像头；这个距离只是摆放起点，不是保证触发的距离。
3. 点击图像窗口，按一次 `a` 开始。若红牌起初就在触发区域，车可能直接等待，没有足够移动距离；这种情况能验证停车等待，但不能记为已测行驶中刹停，下一次需将红牌稍摆远。
4. 车接近红牌时，观察实际是否停下，终端应进入 `SIGNAL_WAIT | WAIT_FRESH_FLOW`。条件是识别连续确认且框的底边到达配置的图像行阈值，不能只凭分数判断。必要时按 `v` 切换 AI/二值画面查看牌面和检测框。
5. 车停下后拿走红牌和手，等约两秒；车应保持停止，不自行起步。
6. 确认前方空闲后，再将绿牌放入视野，保持约两三秒，完整可见。确认 flow 后应自动恢复 `LANE | CRUISE` 并行驶，不要再次按 `a`。放绿牌会放行，操作前要预留行驶空间。
7. 恢复后只走一小段，图像窗口按空格停车，再点终端按 `Ctrl+C` 退出。不要用手在车前拦车。

如果红牌识别了但车辆未停，先停止车辆、保留画面与终端状态，不继续让车撞向牌子。若空格或远程画面迟迟无响应，使用车旁断电手段；远程 GUI 仍存在数秒卡顿，不能承诺按键立即生效。

测试后提供终端末尾截图，并说明“红牌是否让车实际停下、拿掉后是否保持停住、绿牌是否自动恢复、人工停车是否正常”。保持日志目录即可回收完整数据。仅终端状态不能单独证明实际刹车或停车距离；本轮不评估坡面能力。

不带参数时脚本默认为 NO CONTROL 预览。要实跑必须明确写 `drive`，无需给脚本 chmod。
