# 岔路方向复核（2026-10-18）

两轮现场保存的原始图像确认：同一个蓝底白色左下箭头，有时被模型识别为 `yleft`，有时被识别为 `yright`。因此不能整体交换两个类别的编号。本次复用原模型，在独立比赛程序 `trackview_race` 中增加方向复核，没有重新训练模型。

## 修改及作用

- `src/tool/race_direction.hpp`：对模型检出的 `yleft/yright`，在对应原始图像的检测区域提取蓝色牌面与白色箭头，分析箭杆、连接凹角和箭尖的朝向。多个轮廓近似结果方向一致时确认左右；轮廓不清楚、方向矛盾、颜色不符时不把该目标作为方向依据。
- `src/tool/race_perception.hpp`、`race_perception.cpp`：在 AI 工作线程内进行复核，结果与推理使用的同一帧绑定；保留原始类别、原模型分数、复核原因和最终类别。控制循环和显示循环不承担方向图像分析。
- `src/tool/race_preview.hpp`、`trackview_race.cpp`：预览和保存记录新增 `model`（原始类别）、`shape`（复核原因）、`final`（最终类别或 WAIT），日志增加 `direction_checks`。
- `src/tool/race_config.hpp`、`config/race.json`：增加 `verifyForkArrows: true`，默认启用复核。
- `tests/race_direction_regression.cpp`、`tests/CMakeLists.txt`：加入现场样本、镜像方向、非箭头负样本、工作线程与保存结果的回归检查。

本次没有修改组员的 `src/icar`、`src/control`、`src/track`、`src/predeal`、`src/detection`，没有修改原 v6 的 `track_view.cpp`、`trackview_pilot.hpp`、`trackview_config.hpp` 和 `config/trackview.json`。原有速度、转向参数与停车保护保持原值。

## 验证范围

ARM64 交叉编译成功。14 项方向检查全部通过：三张较完整的真实左箭头均确认向左；一张较小且裁切的左箭头拒绝使用；绿色箭头不按蓝色岔路箭头处理；水平镜像的右箭头方向检查及负样本、线程和保存记录检查通过。原转向、串口故障、显示延迟、比赛状态机回归检查也通过。

真实右牌尚未收到，镜像测试不能替代真实右牌测试。此复核仅覆盖蓝底白色斜向箭头，并依赖模型先检测出左右岔路候选；不能解决所有漏检或其他类别的误检。预览上的分数仍是原模型分数，不是复核后的方向置信度，也不代表真实准确率。车辆 NPU 上的新版端到端运行仍需现场静止验证。

## 上传及静止复测

本地交付目录：`D:\智能小车\race_update_20261018\fork_direction_fix`。

退出旧程序后，将以下三个文件一起上传到自己的小车目录 `/root/track-trial-20261010/bin`，覆盖同名比赛版文件：

1. `trackview_race`
2. `librace_npu_backend.so`
3. `race.json`

执行文件与插件必须成套更新，本次结果结构有所扩展。保留自己调好的 `trackview.json`，不需要上传交付目录中的参考副本。原 `trackview_fixed_v6*` 不需覆盖。

```bash
cd /root/track-trial-20261010/bin
chmod +x ./trackview_race
./trackview_race --config ./trackview.json --race-config ./race.json --no-control
```

`--no-control` 不打开小车控制串口，不发送运动命令。先完整摆放左、右蓝牌分别测试，避免箭尖或牌面紧贴画面边缘。

左牌应显示 `shape: ARROW_LEFT`、`final: yleft`；右牌应显示 `ARROW_RIGHT`、`yright`。即便 `model` 仍显示错误类别，最终方向应经复核纠正。`final: WAIT` 表示该帧方向不可靠，需调整距离、角度或让牌面完整进入视野，不能算方向识别成功。按 `s` 保存对应帧，按 Esc 退出。确认左右都稳定后再考虑运动测试。
