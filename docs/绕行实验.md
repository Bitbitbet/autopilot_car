# 低速直道锥桶绕行实验

本入口仍为 `trackview_race` 和 `run_car.sh`。`drive` 继续采用原来的障碍停车；只有显式执行 `bypass competition` 才启用标定后的绕行控制。该功能属于现场待验证的实验，尚不代表已完成比赛全部任务。

## 1. 更新同名文件

先退出车上的旧程序。从电脑 `race_release` 直接复制以下4个文件，覆盖车上现有运行目录里的同名文件：

`trackview_race`、`librace_npu_backend.so`、`run_car.sh`、`release-manifest.json`。

保留该车自己的 `trackview.json`、`race.json`、`navigation.json`、模型和镜头标定。新文件必须配套，启动器会核对主程序与AI适配库。以后直接更新这个目录，不再生成压缩包；已有旧压缩包不代表最新版本。

以下命令均在MobaXterm已登录小车的SSH终端执行。先进入原来存放 `run_car.sh` 的 `bin` 目录，然后执行：

```bash
chmod +x ./trackview_race
```

## 2. 当前车做一次地面标定

原来的 `calibration.xml` 用于去除镜头畸变；绕行还需要把图像对应到实际地面距离。相机角度、高度、安装位置改变，或更换车辆后，须重新做本节。

1. 选平整直道，把小车摆在45厘米宽白色路面的中央，车头对正道路方向，轮子摆正，前方至少留出1米直道。先拿走锥桶和路牌。
2. 用尺从车头最前端在地面的垂直投影开始，沿道路向前量25厘米和65厘米。
3. 在25厘米横线上标记道路左边缘和右边缘；65厘米处同样各标一个点，共4点。两侧间距应为45厘米。可在白路面外侧贴小标记，点击白路面的真实边缘与横线交点，避免标记遮住道路边线。不要从摄像头或车轮位置开始量。
4. 执行下列命令。本模式只打开摄像头和图像窗口，不创建车辆串口、手柄或AI后端，不驱动车轮。

```bash
bash ./run_car.sh calibrate competition
```

5. 在标定窗口按 `f` 冻结画面，然后用鼠标依次点击：**近左 → 近右 → 远左 → 远右**。近处为25厘米，远处为65厘米。画面上的1、2、3、4对应这四个点。
6. 确认没有点到车壳、标记中心或错误边缘，按 `s` 保存。终端应显示 `[Ground] Saved ground-calibration.json`。点错按 `r` 重来；`q/Esc` 取消，不改写既有标定。
7. 如果窗口曾刚启动便显示 `Cancelled`，更新主程序后重试；旧版GTK/X11的窗口状态返回未知时，旧代码可能误判为关闭。现在使用 `q/Esc` 或终端 `Ctrl+C` 退出，不依赖窗口可见性查询。
8. 如果四点没有全部入镜或程序拒绝点位，先保留画面说明原因，不要随意点其他位置。标定假设道路平坦，车宽18厘米、车长约31厘米、白色路面宽45厘米；尺寸不符时不能沿用这组参数。

标定生成 `ground-calibration.json` 和同名 `.png` 原图。它们保留在当前车上，不用另一辆车的文件覆盖。文件会与当前镜头标定关联，镜头文件变化后旧地面标定会被拒绝。

### 2.1 运行时路宽尺度（2026-10-27 新增）

四点点选给出地面的初始透视映射与米制尺度。点选误差或车体姿态变化可能造成尺度偏差；2026-10-27 现场出现过实测45厘米被换算成51～53厘米，导致整轮 `GROUND_LANE_WIDTH_MISMATCH`。按已知路宽作有限修正能补偿整体尺度误差，但不代表纵向距离、轮角/PWM关系已经完成实车标定。

现在 `bypass` 启动后会先用当前画面的左右路沿测一次路宽，再按配置的45厘米锁定一个有限尺度修正（允许范围 0.80～1.30）。锥桶位置、规划路线和地面视觉里程使用同一个米制，不再各算各的。当前车相机未动、仍在45厘米直道上时，沿用现有标定即可，不必为这一版重做。

- 终端和画面底部会显示 `raw lane ..cm x..`：前者是四点标定原始换算出的路宽，后者是锁定的尺度系数。例如 `raw lane 53cm x0.86` 表示画面里的路面比标定值宽约16%，已按45厘米修正。
- `MANUAL` 阶段尺度会随当前画面小幅跟踪；按 `a` 进入自动后冻结，绕行过程中不再改变米制。
- 只有左右两边平行、逐行宽度一致、且跨越0.2米以上地面距离时才接受。超出 0.80～1.30、路面不一致或修正后仍明显偏离45厘米会停车。自动阶段使用同一3.5厘米路宽误差界限，取消额外2厘米均值门槛；同时按最窄有效行与配置45厘米的较小值检查车身，不把观测偏宽当成新增空间。法向宽度会扣除车身夹角的影响。`lane_width_observed_m`、`lane_width_measured_m`、`lane_width_used_m` 及有效/拒绝行数用于解释实际处理。
- 这不是取消几何检查，也不能替代标定：点位顺序、左右边缘和道路方向仍来自四点标定。换车、换相机角度或换到明显不同的路面后仍要重做第2节。


## 3. 第一轮实际绕行

2026-10-28最新状态：用户反馈普通弯道已可直接转弯。本次两轮实测运行于drive普通模式，停车轮为正常障碍停车，另一轮暴露漏检后自动放行的问题。现已修复近桶停车义务保持，并补充有限已定位参考图恢复。下一轮绕行用 `bash ./run_car.sh bypass competition`，先不按a，确认已看到桶且出现BYPASS_RIGHT/BYPASS_LEFT可执行路线。没有确认目标/鲜活路线时，程序拒绝启动绕行。完整实车绕桶仍待验证。

1. 继续使用平整直道，先只放一个静态锥桶。放在道路左侧、前方约45–55厘米处，右侧留出足够空间，不能把18厘米宽车身强行挤进窄缝。先不叠加施工牌、斑马线、弯道或第二个锥桶。
2. 执行：

```bash
bash ./run_car.sh bypass competition
```

3. 默认仍为 `MANUAL`，不会自行启动。图像正常后点击图像窗口，按一次 `a`。初始巡航、弯道和降级速度仍为0.10 m/s，最高可调上限10 m/s，不再额外限制为0.10。`+`/`-`调巡航、`]`/`[`调弯道、`.`/`,`调降级速度；任务和道路质量仍约束实际速度。手动油门禁用。
4. 条件满足时应出现 `BYPASS_RIGHT`，车辆实际向右调整路线绕过左侧锥桶。锥桶处于右侧时应为 `BYPASS_LEFT`。程序使用新图像连续修正路线，不按固定时间盲打方向。
5. 锥桶进入近处后，即使检测框离开画面，也需要连续的地面视觉运动估计，并保留锥桶地图。必须估计31厘米车身及余量已经全部通过，才出现 `BYPASS_RETURN`；回到中线且连续确认后为 `BYPASS_COMPLETE`，随后恢复普通巡线。
6. 在开始偏转、经过锥桶和回中时分别按 `s`。终端先显示 `Queued`，后台保存后显示 `Saved`。这不会让图像编码阻塞控制线程。
7. 现场观察实际车轮和车身。看到方向相反、贴边或擦碰趋势立即停车：图像窗口空格停车；`q/Esc` 或SSH终端 `Ctrl+C` 停车退出。首次实验由一人在车旁留有断电手段。
8. 左侧锥桶通过后，再做右侧锥桶；两边各完成一次后，再各复测一次。每轮先退出，再移动道具。

### 本轮实跑顺序（2026-10-28 近桶视觉恢复修复）

1. 退出旧程序，替换本目录最新 `trackview_race` 和 `release-manifest.json` 即可。后端和启动脚本本轮未变；此前未完整更新过的车辆仍按第1节复制4个配套文件。保留车上 `ground-calibration.json` 和镜头标定。
2. 用上面的同一条 `bypass competition` 命令启动。左侧单锥桶、右侧留通路，车头到桶约45～55厘米。可在图像窗口把巡航、弯道、降级速度都调到0.15～0.20，再按 `a`；启动值仍为0.10，上限仍为10。每次按键增加0.05，实际速度还受道路/任务限制。
3. 重点看是否更早建立侧向偏移，近桶时是否保持通道、车尾通过后是否回中。新搜索代价提前约45厘米开始向侧方通道中部过渡，车尾通过前保持侧方参考；完整车身、道路边界和转向扫掠仍逐段检查。米制预瞄采用实测轴距20厘米；满舵45度仍是待实测映射初值。反向舵也可能是在消除车头夹角，不能只凭PWM符号判断回中过早，应同时看实际横移和车尾净空。
4. 已确认锥桶短暂漏检时，最多350毫秒使用同一有效视觉坐标系中的地图重新规划，并额外膨胀预测障碍；超过期限且尚未满足既有近桶侧向净空条件时停车重识别。近桶历史投影遮罩现在也用于路沿恢复，恢复首帧先用当前已验证的真实位姿投影；视觉里程保留650毫秒的检测区域遮罩，排除图像下方中央车身。`STOP_AND_REPLAN` / `STOP_AND_REACQUIRE_TARGET` 保持零速，不用旧的0.4秒计时锁死。
5. 绕行已开始时，视觉失败先显示 `VERIFY_LAST_GROUND_REFERENCE` 并保持零速。保留桶地图和最后可靠关键帧，主参考最多跨650毫秒；主参考退化时，在距最近成功定位800毫秒内尝试最多4张已定位旧图，旧图最长1.2秒。所有候选保持同一刚体、内点、尺度、残差检查，并检查与最近可靠位姿连续性；通过后再连续确认3条新路线才继续。持续不能接回时锁停，不盲补里程。尚未开始绕行阶段仍保留3次/280毫秒重建机制。
6. 左侧成功后做右侧单桶，确认向左绕行。再做一次运动中空格停车，然后按 `a` 恢复，核对是否重新确认路径。
7. 两侧绕行都通过后，才叠加已有的限速/解除限速、红牌停车/绿牌放行；用 `drive competition` 检查这部分整合行为，该模式仍是遇障停车。施工区主动穿行、停车入库和终点/圈数仍需继续开发，不是本轮交付内容。
8. 中途再次停车时按 `s` 保存，等 `Saved` 后 `q` 退出。程序也会在运动转为绕行停车时，将匹配的故障原图与导航状态送往有界后台队列，保存在本轮日志 `bypass-stop-evidence/ai-sample-*`；每轮最多8次、间隔至少2秒，队列繁忙可丢弃取证任务，不阻塞驾驶线程编码图像。把整轮日志带回，包括该子目录。`motion_reason` 会区分尺度变化、运动超界、点分布不足及刚体残差等，另有拟合尺度、位移、空间跨度。通道宽度和运动仍是视觉估计。

本版地面特征搜索仍为前方约12～100厘米。接管前按原机制重建，接管后按上面的有限关键帧验证机制保留坐标系。跨帧位移/转角的检查随真实图像间隔增加，尺度、残差及点分布检查继续保留；不是以速度乘时间补里程。模拟检查不能证明真实白色路面一定能提供足够纹理。

## 4. 停车状态如何处理

| 状态或原因 | 含义与下一步 |
|---|---|
| `BYPASS_WAIT` / `BYPASS_CONFIRMING` | 正在等待连续确认的可执行路线；短暂等待属正常。持续等待时保存样本。 |
| `BYPASS_NO_CLEAR_PATH` | 当前几何未搜到可执行路线，先零速重算。`GROUND_CURRENT_FOOTPRINT_BLOCKED` 表示当前车身模型受阻；`GROUND_ROUTE_SEARCH_EXHAUSTED` 配合 `route_blocked_z_m` 标明搜索耗尽位置；`GROUND_ROUTE_IMAGE_PROJECTION_SHORT` 表示图像路径不足。保存日志定位，不仅凭横向缝隙就宣布可转入。 |
| `BYPASS_STRAIGHT_LANE_REQUIRED` | 没有足够的双边直道证据、实测路宽不符或出现弯道/岔路。`reason` 给出具体原因：`GROUND_LANE_SCALE_ESTIMATING`（正在按当前画面测路宽）、`GROUND_LANE_WIDTH_OUT_OF_RANGE`、`GROUND_LANE_WIDTH_INCONSISTENT`、`GROUND_LANE_WIDTH_MISMATCH`、`GROUND_LANE_NOT_STRAIGHT`、`GROUND_LANE_BRANCH`。检查摆车、标定与遮挡。 |
| `BYPASS_VISUAL_MOTION_REQUIRED` | 无法确认地面运动，具体看 `motion_reason`；可能是点少、尺度不一致、空间分布不足或拟合运动超界。等待或加速不能替代里程。保存整轮日志和样本。 |
| `BYPASS_TARGET_LOST_BEFORE_CLEARANCE` | 锥桶在足够接近/让出横向空间前丢失，不能当成已通过。保存样本。 |
| `BYPASS_REPLAN_WAIT` | 几何无路/目标丢失时零速重算；这些暂停不计入25秒执行时限。已保留坐标系的视觉恢复最多800毫秒，其他AI/数据失效仍为400毫秒；真正重置后仍要求重新建图，不能跨坐标系盲用旧桶。 |
| `BYPASS_FAULT` | AI/视觉里程持续失效、反复重置或超过实验时限。锁停后先保存并退出程序，不能反复按 `a` 强行放行。 |
| `BYPASS_PERSON_STOP`、`SIGNAL_WAIT`、`GATE_WAIT`、`REVIEW_STOP` | 行人或其他任务的停车义务优先，绕行不会越权放行。 |

视觉运动来自地面特征匹配与平面刚体拟合，不是车轮编码器，也不是把速度指令乘时间当作行驶距离。单色路面、反光、阴影、纹理不足或相机抖动可能使它停车。当前只适用于平坦直道上的静态锥桶；曲线绕障、动态行人、施工区穿行、泊车和终点任务仍未验收。

## 5. 把结果带回来

退出后，在原 `trackview_logs` 目录中找到这次最新的运行子目录，复制整个目录回电脑的约定结果目录。不要只复制终端截图。

保留 `control.csv`、`race.csv`、`bypass-control.csv`、`navigation.jsonl`、`detections.jsonl`、`ground-calibration.json`、各配置快照、`ai-sample-*` 以及 `event-*`。另说明：锥桶在左还是右、是否真正绕过、有没有擦碰/越线、是否回中、停止时的终端状态。指令日志不能代替现场实际通过的观察。
