# 静止路牌识别测试

本阶段检查 AI 检测效果，不测试车辆运动，不用调 PID。

## 准备

1. 小车正常供电，放在平整、稳定的位置，保持摄像头原安装高度、角度和车壳。
2. 使用实际赛道的路牌，先准备左右岔路牌、限速牌、停车牌、绿色通行牌中的两三种。一次测试一块，先按赛道原本位置摆放。
3. 在摄像头视野内留出近、中、远三个位置，可用现有尺子量距并记录；它们是采样位置，不是统一的识别距离标准。
4. 保持电脑与小车连接，原摄像头程序退出后再启动预览，避免争用摄像头。
5. 准备空场景作为对照，用来检查没有牌时是否误报。不需要先购买新设备、拆车或重新训练模型。

## 上传文件

电脑上 `<实验资料目录>/race_update_20261016/preview/` 内的三个文件：

- `trackview_race`
- `librace_npu_backend.so`
- `race.json`

一起上传到 `/root/track-trial-20261010/bin/`。新程序与其插件必须来自同一版本，不能只更新其中一个。保留小车现有的 `trackview.json` 和真实相机标定文件。

启动：

```bash
cd /root/track-trial-20261010/bin
chmod +x ./trackview_race
./trackview_race --config ./trackview.json --race-config ./race.json --no-control
```

`--no-control` 不打开电机串口和手柄，不发送运动命令。AI 推理和摄像头仍工作。启动时可能先编译已有 NMS 模块。

## 看哪个窗口

看 `AI detections` 窗口：左侧显示实际参与推理的那一帧和检测框；右侧显示类别及模型分数；顶部显示帧号、结果年龄和 `FRESH`/`STALE`。

| 实物 | 期望类别 |
|---|---|
| 左岔路指示牌 | yleft |
| 右岔路指示牌 | yright |
| 限速 / 解除限速牌 | limit / unlimit |
| 停车场指示牌 | park |
| 停车/禁行指示牌 | stop |
| 绿色通行牌 | flow |

`park` 与 `stop` 不同，普通左转牌 `left` 与左岔路牌 `yleft` 也不同，应按实际图案区分。

## 每一块牌的测试方法

1. 先不摆牌，观察几秒是否出现错误框。
2. 先在正常赛道摆放位置放一块牌，手离开画面，保持 3—5 秒。
3. 检查框是否落在牌上、类别是否对应、帧号是否继续变化；这三项一起判断。
4. 换近、远位置各测一次，再测试稍微侧向的角度与正常场地光照。
5. 拿走牌，确认后续新帧中的检测消失。旧帧显示期间注意顶部年龄，不能只看一个冻结的正确框。
6. 成功、漏检和识别错误时都可以点击 `AI detections` 窗口按 `s` 保存样本。按 Esc 退出。

置信度是模型分数，不是实际准确率。例如显示 0.90 不代表在赛道上有 90% 的正确率。默认显示阈值为 0.65；先收集结果，再判断要调整阈值还是改进模型。

## 如何反馈

先发一张正确识别截图和一张失败截图，并说明实物种类、距离、当时光照。随后可用 MobaXterm 下载本次日志下的 `ai-sample-N` 文件夹，其中包含对应原图、画框图和 JSON。没有框也要保存，方便区分漏检与画面里目标本身不可见。

`FRESH` 但目标无框：先分析画面、标签和检测阈值。`STALE / WAIT` 或 `AI FAILED`：先检查推理耗时、模型初始化和运行环境。程序无法启动时，发完整终端输出，此时还不能判断路牌识别能力。

静止测试通过后，再单独进行低速接近路牌的测试，以验证运动模糊和提前识别距离。静止识别成功不能直接证明高速时能及时完成任务。
