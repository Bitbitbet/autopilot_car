# 智能小车：固定程序与验证入口

主程序固定为 `trackview_race`，统一入口为 `run_car.sh`。后续改进继续更新这两个入口及配套 AI 适配库，不再通过更换日期版程序进行日常测试。

2026-10-28普通转弯补充：集成入口已使用v6的AutoPilot，但原逐行宽度只在近直道学习、每次重启清空，直接在弯道起步可能出现WIDTH_UNAVAILABLE。现在当前车ground-calibration.json通过镜头验证时，会补充标定推算的逐行宽度参考，原转向和实时双边校验保持。启动显示 `[Lane] Current-camera calibrated width reference rows=...`；width-profile.csv的calibrated_reference区分标定参考与实测学习。没有该文件或验证失败时保留原学习机制，不套用其他车数据。

用户已反馈普通弯道可以直接起步转弯。`bash ./run_car.sh drive lane` 为普通巡线和遇障停车，不会自动绕行；显式绕行入口为 `bash ./run_car.sh bypass competition`。bypass必须先看到已确认锥桶及鲜活可执行路线才允许按a启动。完整真实绕桶仍未验收。

2026-10-28近桶停车保护修复：已接受的近桶立即停车，不再等凑满3帧；近桶停车义务不再由漏检自动清除。普通drive停在 `CONE_ROUTE_OR_RESTART_REQUIRED` 时，检查并退出处理障碍后重启；只有验证通过的绕行授权可以解除对应桶的义务，不能靠绿牌或反复按a放行。

2026-10-27新增显式的直道静态锥桶绕行实验。**`drive` 仍为巡线与障碍停车；要实际绕行，先 `calibrate competition`，再 `bypass competition`。** 具体摆点、点选及实跑步骤见同目录的[绕行实验](绕行实验.md)。本页下文的像素路线说明适用于原 `preview/drive` 模式，不代表 `bypass` 的米制控制。发布直接更新 `race_release` 固定文件，不再生成或刷新压缩包。

## 本次变更

停车牌：保留模型真实分数。普通检测仍使用原配置的 `confidence`（目前0.65）；仅对 `stop` 采集0.35以上低分候选，并用同一推理原图检查红色区域、中央白横杠和上下红色区域。通过后仍需连续3次新观测、未过期，以及原来的接近位置条件，才能触发对应任务。关闭 `verifyStopCandidates` 可以恢复单一阈值行为。

斑马线：原模型权重保持不变。仅 `cross` 额外保留0.10以上候选，低于普通阈值时必须与同一原图的条纹区域重合。几何检查要求至少6条深色短条、规则间隔、条间及上下的浅色路面；模型没有输出 cross 时，也可提供独立条纹证据。处理在AI工作线程中进行，不在转向循环中重复计算。`verifyCrosswalkGeometry=false` 可关闭此扩展，`crossCandidateConfidence` 仅影响 cross 候选。

几何证据显示 `cross GEOMETRY`，没有模型置信度；低分模型框通过校验显示 `cross 0.xx CHECKED`，保留真实分数。日志的 `crosswalk_geometry` 单独记录来源、条纹数、对比度和框，`model_score=null`；不在模型检测列表中伪造高分结果。

绿牌、岔路、限速及其他类别继续使用原阈值。绿牌仍需连续确认，低分停车牌或斑马线复核不能用于放行。拿走红牌不能取消已进入的等待状态。

右侧匹配AI画面会保留真实分数，低分且通过图形复核时标注 `CHECKED`；未通过时标注 `REJECT`。单帧 `CHECKED` 不表示车辆一定已停车，仍需查看终端比赛状态及现场车辆。

## 安装与原有资源

在 `preview` 和 `drive` 模式中，绕障规划为后台观测扩展，原模型、巡线控制和实跑障碍停车策略继续使用。预览的右侧匹配AI图像显示青色建议中心线和假设车宽边界；`OBS_BYPASS_LEFT_PREVIEW` / `OBS_BYPASS_RIGHT_PREVIEW` 表示图像上找到左/右通路，`OBS_NO_CLEAR_PATH` 表示当前假设车宽下没有连续空间。`OBS_CONFIRMING`、`OBS_AI_STALE`、`OBS_LOST_BEFORE_NEAR`、`OBS_BRANCH_AMBIGUOUS` 等状态分别表示待确认、结果过期、目标过早丢失、岔路不明确。标记均属于预览，不代表已完成真实绕障。

道路一侧出画面时，未入镜的边界仍标为未知；规划只在画面内可见通路范围里进行。若找到局部通路，显示橙色 `OBS_VISIBLE_PASS_LEFT_PREVIEW` / `OBS_VISIBLE_PASS_RIGHT_PREVIEW` 和 `VISIBLE ONLY / PIXELS`。这类结果继续保留 `would_stop=true`，不表示完整道路或实车净空已经验证；空间不足仍为 `OBS_NO_CLEAR_PATH`。日志新增可见范围、每行边界是否入镜及裁边行数，假设宽度的参照明确为画面内通路。终端状态打印最多每秒一次，原始检测 JSON 和界面仍正常更新。实车的路线工作线程只保留最新待处理帧，`navigation.jsonl` 记录每次完成的结果，并包含被替换的待处理帧数、计算耗时和发布时年龄；不能把路线记录条数当作摄像头帧数。路径搜索保留半像素位置，按原配置限制横向变化，不放大允许的斜率。

配置 `navigation.json` 的模板见仓库 `config/navigation.json`。当前车由现场量得车宽18cm、白色路面宽45cm，已将模板的 `previewVehicleWidthFraction` 设为18/45=0.40；未安装此配置文件时，程序仍使用保守的内置0.55。换车或换赛道需重新量取，不能沿用本车比例。`previewVehicleWidthFraction`、`previewClearanceFraction` 用于图像空间预览，视野被裁切时比例的参照仍是可见通路，尚未标定为米制车轮净空；`obstacleMode` 仅支持 `preview` 和 `off`。`drive` 模式也在独立工作线程中计算并记录建议路线，路线队列只保留最新待处理帧；巡线与障碍停车仍由原控制策略执行，建议路线不接管方向控制。实际绕行使用新增的地面标定和 `bypass` 实验入口，不能只调整上述像素比例来驱动车辆。

发布目录中的以下4个运行文件放入车上现有运行目录的 `bin`：

- `trackview_race`
- `librace_npu_backend.so`
- `run_car.sh`
- `release-manifest.json`

安装前退出旧程序。主程序与适配库必须一起更新，清单会核对两个文件的SHA-256，不能混用旧库。旧的日期版比赛程序不作为本次入口，v6巡线备份仍保留。

继续使用该车原有 `trackview.json`、`race.json`、`../res/models` 和 `../res/calibration`。不要用交付包替换组员工程、原模型、标定或下位机固件。另一辆同型号车仍需核对自己的相机标定、舵机方向与中位等参数。

## 固定命令

```bash
cd /root/track-trial-20261010/bin
chmod +x ./trackview_race
bash ./run_car.sh preview signal
```

这是下一轮优先使用的命令，不驱动车轮：

1. 放在当前实验室平整赛道，确认图像与AI正常。识别不需要按 `a`；要计算 `LANE/SIGNAL_WAIT` 等比赛状态，再在图像窗口按一次 `a`。
2. 依次检查空路面、白纸、绿牌没有被补认成stop；红牌靠侧边和完整入镜时能显示真实分数及必要的 `CHECKED` 标记。
3. 红牌足够接近时应进入 `SIGNAL_WAIT`，拿走后仍等待，确认绿牌后恢复 `LANE`。接近阈值依旧为框底边达到配置中的 `triggerRow`（目前145/240行），不能用肉眼百分比代替。
4. 在出现问题的画面按 `s` 保存匹配图像与接受原因；用 `q/Esc` 或终端 `Ctrl+C` 退出。

本次斑马线优先用 `bash ./run_car.sh preview competition` 复测，不驱动车轮。识别本身不用按 `a`：依次检查远、中、近距离斑马线显示 `cross GEOMETRY` 或通过校验的 cross 框，再检查空路面、车头图案、施工牌和锥桶未被补认成斑马线。`preview` 与 `drive` 均可按 `s`：先将匹配图像入队，再由专用线程编码和写盘，队列满时拒绝新请求，不等待磁盘。退出时先停车，再完成队列中的保存。

要检查组合状态，在 preview 窗口按 `a`，展示近处红色停车牌进入 `CROSS_APPROACH`，保留红牌并让斑马线在画面中从远处移到近处，框底边达到205行后再移出下方。仍需3次连续新观测、消失至少0.25秒，才进入 `SIGNAL_WAIT`；单独看到斑马线不会凭空增加停车信号。若6秒内没有证据证明通过，保留 `CROSS_PASS_NOT_VERIFIED` 停车复核。预览确认后，才用 `drive competition` 在实际赛道低速测试停车位置与绿牌恢复；205是像素阈值，需现场验证，不能据此保证实际停车距离。

预览验证后再安排实跑，固定命令只需换一个模式：

```bash
bash ./run_car.sh drive signal
```

`drive` 会真实控制车轮，默认MANUAL，按 `a` 才自动巡线；图像窗口空格停车，终端Ctrl+C退出。测试选平整直道、牌面不阻挡行驶道路，车旁保留断电手段；远程GUI仍可能卡顿，不能承诺按键即时响应。绿牌确认后会自动恢复行驶，展示前先留出空间。

其他场景同样通过固定入口选择：

| 场景参数 | 用途 |
|---|---|
| `lane` | 普通赛道连续巡线，比赛规则沿用原race配置 |
| `signal` | 独立停车/放行测试，配置副本关闭先过斑马线条件 |
| `limit` | 限速/解除限速，副本限速设为0.08 m/s（不低于该车minSpeed） |
| `competition` | 沿用原比赛任务规则，初始速度仍为0.10 m/s，并非已验收的比赛配置 |

原 `preview/drive` 场景启动时的巡航、弯道和降级速度仍为0.10 m/s；最高可调上限已按用户要求于2026-10-24恢复为10 m/s。图像窗口中的 `+`/`=` 与 `-` 调巡航，`]`/`[` 调弯道，`.`/`,` 调降级速度，每次0.05 m/s；重启后回到初始值。10是程序允许调整的上限，不是启动速度或已验证的实车速度。任务和道路质量仍会限制实际速度指令；没有两秒定时退出。脚本从现场配置创建运行副本，保留其他巡线参数，原配置不改写。不带参数默认为 `preview lane`。

## 数据与验证边界

静止预览可使用 `bash ./run_car.sh preview competition`，不用按 `a` 即可计算建议路径。让真实锥桶分别位于路内左侧、右侧和中间，稳定观察至少1秒；检查建议路径是否避开全部障碍、假设车宽边界是否仍在道路内。再摆两个障碍、道路外的锥桶，检查空间不足时停止提出通路、路外障碍不占用道路。可以手动调整小车与道具的相对位置，记录不同距离；本命令不驱动车轮。按 `s` 保存当前画面。

低速动态测试使用 `bash ./run_car.sh drive competition`。初始巡航、弯道和降级速度均为0.10 m/s，图像窗口按 `a` 才开始自动巡线，本轮保持初始速度。沿道路驶近左侧或右侧锥桶时，后台记录同帧路线；原障碍逻辑满足条件后停车，自动绕行动作尚未接管控制。行驶中可按 `s` 保存匹配画面；终端先显示 `Queued`，随后显示 `Saved`。图像窗口空格停车，`q/Esc` 或终端 `Ctrl+C` 停车退出。

样本目录除原图和检测结果外，新增 `navigation.png`、`navigation.json`，记录同一推理原图的预览路线、图像像素单位、假设宽度及拒绝原因。连续规划记录为 `navigation.jsonl`，配置快照为 `navigation-config.json`。过期结果和不同AI序号的路线不会画到当前匹配图像上；原始 `camera.png` 不被画线改写。

要继续施工区、泊车和终点任务，需要补充：施工区/停车场入口与出口在道路哪侧、区域内的标线与车位形状、起终点与普通斑马线如何区分、最终路线及两圈任务顺序。当前入口方向和起终点特征尚不清楚，程序没有填入猜测值。已收到车宽18cm、车长约31cm及路宽45cm。直道锥桶实验仍须建立当前车的地面四点对应关系；现有 `calibration.xml` 只处理镜头畸变，不能代替地面尺度。进一步验证曲线和车辆运动学时仍需量测轴距及舵机响应。

运行副本和启动清单保存在 `run-records/<时间>-<PID>-<场景>`，详细日志仍在 `trackview_logs/<毫秒时间>-<PID>`。`detections.jsonl` 保留原始分数，并追加是否接受、是否图形复核、接受/拒绝原因及独立斑马线几何证据。

斑马线扩展已用本次保存的3张远近正例及查看确认的28张普通路面、红绿牌、白纸、车头图案反例回归，并加入合成条纹、颜色、棋盘格、分隔带和状态机测试。这些样本参与了开发，不能用作独立准确率评估；强反光、遮挡、不同赛道材质、更多距离和现场连续运动仍需复测。原0.10 m/s红绿牌启停的实车结论不等于新版本斑马线停车已经验收。

截至2026-10-24，已完成本地整合和离线回归，并在原实验室T710上完成多次0.10 m/s红牌停车、绿牌恢复实跑。现场人员观察到实际启停，两轮日志均记录了红牌触发等待、等待期间零速度指令及绿牌确认后恢复。日志指令不是独立实测车速，尚无停车距离测量。最高可调上限恢复为10后的更高速度未验证；真实岔路、坡面通行和另一辆车的标定核对仍待现场条件。施工与泊车专项规划仍未完成，不能视为比赛全部任务通过。
