### 结合本队现状建议执行的顺序（工程建议，不是官方额外要求）

1. 固定摄像头安装和舵机中位，保存标定与当天配置。
2. 在直道、左右弯、Y 岔路各采集连续视频，覆盖不同距离、光照、模糊和遮挡。
3. 统计 15 类标签的漏检、误检和近距离定位误差；按拍摄场次划分训练/验证/测试，避免相邻帧泄漏。
4. 分别验证方向牌选路、限速区、停车牌、道闸，再叠加整圈任务。
5. 记录每次运行的源码提交、模型哈希、JSON、日志和失败图片，不只保存“成功那次”的视频。
6. 低速连续完成整套任务后再调速度；比较完成率、碰撞、任务漏做和整圈时间。
7. 提前演练启动、急停、重新摆车、裁判允许重试的流程和录制分工。

## 4. 本地代码究竟缺什么

| 功能 | v6 `trackview` | 组员 `icar` | 本次新增程序 |
|---|---|---|---|
| 巡线和 PD 转向 | 已有时间归一化、滤波、可信边界和速度平滑 | 另一套中心线与运动逻辑 | 继承 v6，不改其参数 |
| AI 交通标签 | 未调用检测器 | `src/detection` 已有 NPU/ONNX 检测流程 | 复用检测后端，异步最新帧、原图时戳、标签顺序校验 |
| 岔路几何 | Track 有 `spurroad`，默认选择最近白色块 | `fsm/yfork.cpp` 用方向牌与删边动作 | 多帧方向确认 + 多行连通分叉 + 左右通路选择 + 退出与超时 |
| 状态管理 | 手动/自动和丢线停车 | 多个 FSM 通过共享状态和顺序调用叠加 | 统一优先级与秒计时，记录原因 |
| 限速 | 用户 limit/turn/quality | `fsm/slow.cpp`，有帧数超时退出 | 确认 limit 后保持，确认 unlimit 才解除 |
| 停车信号 | 无 | `fsm/cross.cpp`，含帧数等待和退出动作 | 2026 越过斑马线后等待；新鲜绿色牌才释放 |
| 道闸 | 无 | `fsm/stop.cpp`，主要依靠消失计数释放 | 水平杆等待；持续检测同一区域竖直杆才释放 |
| 行人/锥桶 | 无 AI 绕行 | `fsm/obstacle.cpp` 有旧规划 | 接入近处障碍等待，尚未完成绕行路径验证 |
| 施工区 | 无 | `fsm/busy.cpp` 有旧规划 | 标签入口和明确待验证停车，尚未移植完整入区绕行 |
| 自动泊车 | 无 | `fsm/park.cpp`、`fsm/fork.cpp` 有旧规划 | 标签入口和明确待验证停车，尚未移植入库/出库 |
| 终点/双圈 | 无独立定位 | `cross` 与停车退出有耦合 | 仍需最终地图定位，不用任意斑马线计圈冒充完成 |
| 实际速度 | UI 为发送速度，串口反馈解析未实现 | 同样依赖下位机 | 保持事实，不把命令速度当实测速度 |
| 米制车轮净空 | 没有 | 有映射相关工具但不代表标定有效 | 待地面标定，不伪造米制距离 |

旧模块“存在”不等于“已通过本届全部任务”。例如 `yfork` 中计数未在所有无检测帧清零，且标牌触发后直接删线；`slow` 超时会退出限速区；`cross` 的定时行为与今年任务需要重新核对。这次不改组员文件，而在独立入口处理这些问题。

## 5. 组员说的三部分如何实现

### AI 标签识别

摄像头去畸变后的原图 → 单槽最新帧队列 → 已有 T710 模型推理 → 带帧编号和拍摄时间的检测快照。巡线线程只读取快照，不等待推理；同一快照只能为确认计数贡献一次。低置信度、越界框、非法类别被丢弃。识别超时会停止自动运动，不解除已有任务停车。

当前模型标签依次是 cone/person/busy/limit/unlimit/stop/flow/park/gate/cross/fork/left/choice/yleft/yright。顺序不同会拒绝启动；这项检查保证映射关系，不保证模型检测精度。模型是否识别“抬起的杆”，需要真实视频检验。

### 岔路识别与路径

`yleft/yright` 连续新观测 → 记住方向 → 图像路面出现连续多行可通行分叉 → 从近到远跟随指定的连通白色块 → 将这条路径的双边界交给 v6 → 分叉持续消失后回归巡线。方向冲突、没有方向的分叉、支路丢失或选路超时都有可见的等待/故障原因。

与直接删边相比，该路径保留实际可见的道路边界，但仍基于像素。当前分叉几何属于基线算法，需用你们实际岔路视频验证，不保证所有岛状标线和阴影下均正确。

### 标签指导状态机

检测结果只提供证据，由任务状态机决定是否改变道路、限速或停车。当前优先级为：感知/路径故障、待验证锁定任务、道闸、近处障碍、停车信号、岔路、普通巡线；限速区状态独立保存。人工急停和串口看门狗始终在任务之外生效。

状态机按时间计时，标签确认按新推理结果计数。原来的 maxSpeed、巡航/弯道/降级配置保持原值，额外的任务速度只在 `trackview_race` 生效。

## 6. 本次交付的边界和仍需要的资料

这是本地可编译、可回放验证的比赛基础集成版，不是全部得分项已完成的最终参赛版。没有上传或启动小车，没有推送 GitHub，没有训练新模型。

要完成其余真实任务，需要：

- 本届北京赛区最终地图、起终点样式及两圈的任务安排；据此设计终点独立识别，不能简单统计所有 cross 标签。
- 你们摄像头拍到的岔路、入库/出库、施工区和障碍物连续视频；已有人工测试截图不能代替动作全过程。
- 从本地图片备份筛选有效样本，核实哪些另有标注，补齐 15 类类别表与标注质量检查；不必重新上传整个图片目录。
- 车辆宽度、轴距、摄像头离地高度和地面标定点；用于检验避障与车轮净空。可从公开规格及外部量测取得，不要求拆公用车。
- 如需保证测速合规，需要场地测速结果或已确认的下位机速度反馈协议。

本次没有把定时盲转、猜测车宽或失去目标后的强行继续行驶包装成完整避障/泊车。

## 7. 逐项验收表

| 测试 | 通过标准 |
|---|---|
| 原 v6 回归 | 原有控制器、模拟串口和界面延迟测试继续通过 |
| AI 队列 | 推理变慢时没有无限帧积压，保留拍摄时戳 |
| AI 重复/过期 | 重复一次结果不会触发连续确认；过期自动停止 |
| 岔路 | 左/右方向和几何都满足才选择；无牌/冲突等待 |
| 限速 | 牌离开视野仍限速；确认解除牌才恢复 |
| 道闸 | 不会因几帧漏检就放行；真实竖杆须验证模型是否能识别 |
| 停车信号 | 越线证据与停留阶段分别记录；绿色牌不能覆盖仍存在的停车牌 |
| 泊车/施工 | 明确显示规划待验证，不报告成功 |
| 实车 | 先不发控制预览，再逐项低速验证，最后双圈；尚未执行 |
