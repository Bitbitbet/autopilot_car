## 停车相比早期版本

停车继续采用33°实验转向模型、航向落后补偿、入口可压线区域的可行前进转向恢复；出库用10cm预瞄和平均曲率，避免已偏过参考仍反向满舵。昨晚后期又增加了640×480采集归一化到320×240、GUI/控制/AI分线程、停稳抖动等待并重计3秒、按实际后轴距离1.5cm整理倒车轨迹。33°及毫米级观测容许量仍是工程试验值，不是独立物理标定。日志已确认过入库与3秒停稳，完整实车倒车出库仍待验证。

本轮主要把已有停车模块接入总控：进入停车通道后，看到完整左侧车位口即先停下，自动规划并启动入库；完成停车和返回通道后恢复巡线。用户确认车位均为空，不固定编号。

## 两种总控路线

| 模式 | 使用场景 | 路线与结束 |
|---|---|---|
| mission-lab | 当前单圈白色实验室 | 普通巡线、交通规则、新绕障；不套用比赛停车路线；回实际起点按n结束 |
| mission | 晚上的比赛同形黑色赛道 | 第一圈选左侧停车通道，停车/停3秒/倒回通道，出口选左；回起点按n进入第二圈；第二圈在分叉选最接近原车道延续的直行支路，走外圈；回起点再按n结束 |

这份两圈顺序来自用户此前两张路线图。没有固定起终点标记，故n是操作员的计圈/终点确认，不是假装通过箭头定位。后续如增加固定标记，可替换这一事件源。

普通曲线继续由巡线处理，不按帧计数盲转。计划方向只有在看到连通分叉时才交给分支跟随器；地面箭头用于辅助约束，如果清晰识别到的允许方向与计划冲突则停车并记录原因。地面箭头识别是基于形状和对比度的初版，尚需真实赛道样本验证；GROUND ? 表示没有可靠识别，L/S/R分别为左/直/右。单个箭头不能证明全局位置或已经回到起点。

## 新绕障

参考读取：[iCAR 2025公开示例 busy.cpp](https://github.com/wslzx6/icar_autopilot_2025th/blob/master/src/fsm/busy.cpp) 使用障碍左右间隙判断方向，Bezier修补一侧边缘，再交给原控制器跟随；[park.cpp](https://github.com/wslzx6/icar_autopilot_2025th/blob/master/src/fsm/park.cpp) 记录入库轨迹用于倒车。本项目独立实现相关思路，未复制第三方代码、模型或车辆参数。

新增 bypass-virtual：从与AI结果对应的图像构造虚拟边界，选择左/右空隙并限制锥桶区域的车辆投影包络，再由v6控制器跟随；不要求累计视觉里程。按已知车宽18cm、道路45cm估计比例，另加每侧5mm工程余量。多个锥桶共同检查，行人、关闭道闸和原交通停车优先。

2026-10-30现场修正：本轮白色赛道日志显示模型检测框反复缺失，导致路线清空、确认计数重置及v6反复等待0.25秒恢复。已确认锥桶现在允许用当前对应图像作局部多尺度模板匹配，最长桥接1秒模型漏检；模板只由真实AI框更新，匹配不到、图像过期或空间不通仍停。短暂缺帧保留确认历史，同一目标恢复不再从零计数。这是图像跟踪，不是里程测量或已绕过的证明。

后续运行1793349646956-22887发出过前进指令，但PWM只有1523～1542，绕行偏移被大量近直行路径点稀释。停止图复现了CONE_ENVELOPE_OVERLAP，其中一个边界仅因浮点运算误差侵入约0.000008像素。已将比较加入0.001像素数值容差，保留原车宽/锥桶余量；路线目标改为空隙中间，入口平滑段从60延长到140图像行，远端平滑段由45延至80行。这些行数是图像空间工程参数，不是实测转弯距离。原v6巡线增益和速度设置保留。同一停止图检查中，新路线通过空间与v6就绪检查，虚拟绕行PWM为1591（普通巡线为1509）；这是离线指令结果，实际转向和完整通过仍待实测。

增加绕行转向补偿：前一轮有正向速度指令，且连续新画面的同向路径偏差超过8像素、持续0.25秒未明显改善时，逐步增加同向PWM，额外补偿最多120。偏差下降则退补偿，接近目标、误差换向、停车、图像失效及进入回中阶段均清除或退出补偿。它依据图像误差推断跟随不足，不读取真实舵角，也不把速度指令当作实测运动。保留原PWM端点和每秒600的转向变化限制。单独bypass-virtual及mission使用同一补偿器；日志新增virtual_error_px与virtual_correction_pwm，单独模式另记virtual_base_pwm。初始0.10、最高可调10不变。

三轮后续现场记录及修正：

- 1793355415674-32378：用户确认已绕过锥桶；日志进入保持侧边和回中，随后因BOUNDARY_LATERAL_STEP停车。记录为实际过桶已观察到，完整回中恢复巡线仍未通过。
- 1793355522566-1178：部分过程出现视觉退出状态；另一次贴边位置因VIRTUAL_VISIBLE_WIDTH_REQUIRED等待。停止图中的双边主要位于画面顶部，原路宽拟合区域未包含这些行。
- 1793356290816-8412：车与锥桶同时靠左的压力测试，行驶PWM范围1427～1719，最大持续误差补偿约27.7；多张停止图均为BOUNDARY_LATERAL_STEP，不能单纯归因于没有发出转向。

现在先计算每行由道路、车身宽度和锥桶共同限定的可通行中心区间，再传播相邻行可达范围、反向选取平滑中心线。原先遇到单个目标点突变就停止，现在优先在真实可通行区间内修复；确无连续通路仍停止。正常路宽数据不足时，额外使用画面顶部至第5行的实际双边，最低8个有效采样行；不把被裁掉的边界当作已经观测到。

入绕增加最多40 PWM的即时补偿，条件是目标仍可见、偏差方向与绕行方向一致且超过8像素、前一轮有前进指令。补偿随偏差和锥桶接近程度变化，对准后或锥桶消失进入保持/回中阶段撤掉；与持续偏差补偿相加后的总额仍限制在120 PWM内。PWM与真实轮角未标定，不能把这些数值称为增加了多少度。

本次检查覆盖上述三轮的6张停止图，以及前两轮的漏检/浮点重叠停止图；包含贴边起步、单边裁剪、路径平滑、回中阶段、左右补偿与撤回。离线通过不代替新版本实车完整过桶和回中验收。该轮采集使用192.168.2.2；当前地址以用户最新消息为准。仅更新本地race_release，未上传或启动小车。

近处锥桶消失后，继续依据新鲜道路边缘保持绕行侧，再平滑回线。阶段长度用正向速度指令积分的距离估计：保持0.36m、回线0.12m；零速等待不推进。它不是实测里程，也不是车尾已过桶的证明，日志不会置 rear_passed=true。原米制 bypass 模式仍保留，可作对比。

## 现在白色实验室怎么测

四个固定文件一起覆盖原小车目录，退出旧程序后操作。每次只运行一条，先q退出再换模式。初始速度仍0.10、最高可调10，建议本轮先保持初始速度。

1. 直道放一个锥桶靠左，先无电机预览，再实跑；随后把锥桶放右侧重复。观察是否向空隙侧绕行、是否完整通过、何时回中。预览按a只计算，不驱动车轮。

```bash
bash ./run_car.sh bypass-virtual-preview competition white
bash ./run_car.sh bypass-virtual competition white
```

2. 测单圈总控，按a开始，回到实际起点按n结束；这一模式不会尝试比赛停车。

```bash
bash ./run_car.sh mission-lab competition white
```

## 晚上黑色赛道

```bash
bash ./run_car.sh mission-preview competition black
bash ./run_car.sh mission competition black
```

先预览核对地面箭头、分叉和停车口，再实跑总控。若需要单独确认停车出库，仍用 parking-drive competition black。比赛模式需要原车地面标定和原倒车能力确认文件；实验室单圈与新绕障不依赖这两份停车专用文件，但仍使用原车镜头矫正和AI模型。模型、标定及配置不被启动脚本覆盖。

a开始，空格停，q退出，g在停住/完成后复位；n在指定起点确认计圈/结束；s保存当前摄像头处理图。被中断的停车不会自动续跑，应重新摆到对应起点测试。

`bypass-virtual`及其预览模式中，重复按a只表示开始，不会切回手动。空格停止后，在当前摆正的位置按g清除旧绕行状态，等待新路线，再按a启动；不再必须退出整个程序。原bypass/drive按键行为保留。

## 10月30日：弯道缺边与方向牌引导修正

从192.168.137.157只读采集最新三轮：1793357583979-1717、1793357630906-2691、1793357657822-3133。最后一轮先右绕、保持、回线并恢复巡线；后续出现远处新检测框，再启动左绕，最后为PROJECTED_VEHICLE_ENVELOPE_BLOCKED和VIRTUAL_VISIBLE_WIDTH_REQUIRED。无法仅凭这些框认定是同一锥桶重复触发，因此没有加入忽略所有锥桶的冷却时间。

停止图ai-sample-2的有效双边行只有85～99行。其水平路宽拟合斜率约-2.83，来自弯道形状，不是合理的直路透视尺度；这会在部分远处行把车体包络放大到无法通过。现在拒绝负斜率、过陡斜率和明显残差的路宽拟合；正常巡线时也收集当前双边路宽。在有效参考不超过2秒时，允许以当前可见边界加最近有效路宽重新规划，复用不会刷新参考时间；日志为CURRENT_EDGES_RECENT_WIDTH。重置清除参考。进入近桶通过/回线阶段后，远处弯道断行可以缩短预瞄范围，但必须保留至少35行、70像素跨度的当前连通近路，且不能截掉前方可见锥桶。

方向控制补上两处缺口：普通LEFT牌也经过蓝底白箭头形状复核，横向箭头不再因没有向下分量被拒绝；确认方向后，等待分叉时不再允许普通巡线给出相反方向。远处牌仅约束方向，近牌达到现有triggerRow后进入FORK_SEEK_LEFT/RIGHT，提供90～160 PWM的实验性方向引导。仍使用当前道路质量/速度限制；不是已标定的轮角。最长使用现有forkMaxTime（默认4秒），期间识别到相应可见分叉或朝该方向的连通道路后交回路径控制。未找到时明确报SIGNED_ROAD_REACQUIRE_TIMEOUT，不改选相反支路。行人、道闸、旧图和人工停车仍优先。

引导独立于selectedBranch：尚未找到目标路时不会让总控误计为已完成转弯。修正接入固定trackview_race的drive、虚拟绕障和mission交通控制；组员独立racing可执行文件不在这四文件更新范围内。

离线验证包括：之前各轮绕障样本、最新弯道图在近期有效路宽条件下的连续性及过期/重置、左右引导与相反巡线指令、横向蓝牌、用户手机拍摄的左牌、道闸/旧帧优先、总控交接、停车回归。两张不同时间的现场图用于受控连续性测试，不冒充完整实测时序回放；手机照片通过也不代表车载模型已稳定检出。实车仍需分别确认完整绕过并回线、左牌岔路真正走左路。

## 当前比赛策略：缺边继续回线，压线不作为强制停车

用户已说明比赛赛道无坡道，压线扣分、停车可能结束比赛。本次不新增坡道检测、俯仰估计或坡道专用补偿，仅调整虚拟绕障中的可见道路恢复与边线约束。

最后一轮1793361037142-6149的第669帧仍有有效路宽，第684帧进入近桶消失后的保持阶段，第697帧参考年龄2.052秒，因VIRTUAL_VISIBLE_WIDTH_REQUIRED停车。此次将参考到期改为“尺度不确定”，在当前仍有连通可见路面的条件下继续生成引导，不复用过期参考作为可靠尺度，也不因2秒到期把速度清零。

近桶消失且路宽不完整时直接进入VIRTUAL_REACQUIRE，使用每张新图中的可见道路中心回线，不再持续保持强烈的绕行侧偏移。剩余偏移最多为可见路宽的10%，按0.12m正向指令距离渐退；这不是实测里程。恢复过程中取消入绕附加转向补偿。取得连续5张有效路宽并完成过渡后交回普通巡线；始终缺少完整双边但仍有连通可见道路时，恢复引导继续工作，不设两秒强制停车。新出现的桶重新进入绕障判断。

完整车体留在线内仍作为首选；若它使可见锥桶旁的路径无解，允许放宽为“车身中心沿可见路面行驶、车体可压线”，保留锥桶包络约束。日志virtual_line_crossing_allowed标明使用了这一策略，virtual_width_uncertain标明没有有效完整路宽。该行为属于比赛取舍，并不代表验证了车体始终在线内。人工停止、图像过期、行人/关闭道闸优先仍保留。

验证重点：最后停止图在超过原2秒时限后仍提供可被v6控制器执行的持续非零速度；镜像画面会改变恢复转向而不是重复旧路径；双边恢复后交回巡线；新行人仍优先停车。实车能否完整绕行并回线仍需现场确认。交付入口和四文件保持不变。
