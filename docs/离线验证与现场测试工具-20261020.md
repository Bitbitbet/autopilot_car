## 边界审计的实际结果

`tests/race_boundary_audit.cpp` 直接调用当前 C++ 几何函数，生成 33 个合成案例及对应二值图，并逐例检查左右镜像。结果为：15 个案例与预设场景相符，17 个真实分叉边界案例未被识别，1 个同像场景无法仅凭几何确定语义。五项基础场景检查通过。

这些案例是主动构造的边界条件，数量分布不代表真实赛道准确率。报告会将未识别的案例标为 `missed`，不会把测试程序正常退出当作分叉识别全部通过。

已确定的限制：

| 场景 | 本次观察 | 后续需要 |
| --- | --- | --- |
| 一侧支路不足 30 像素 | 20、25、29 像素的案例未识别，30 像素起满足本例条件 | 实拍确认有效识别距离，不能只凭像素阈值换算米 |
| 黑色分隔带不足 12 像素 | 5、10、11 像素被当作细小黑点合并 | 实际岔路远端画面及噪声样本，评估阈值与误报之间的取舍 |
| 全路面横向遮挡 | 连续 2～20 行的五个案例均中断持续分叉证据 | 摄像头/手臂遮挡与真实道路中断的分辨策略 |
| 两条路在画面内重新合流 | 多个有限分隔带案例未按岔路处理 | 结合方向牌和实际赛道结构，验证有限分隔岛专项策略 |
| 路牌框恰好覆盖真实分隔带 | 几何会被牌面排除区域合并 | 对应场景原图、检测框及同帧证据，不能直接取消路牌排除规则 |
| 深色竖条与道路分隔带同像 | 单凭这一张二值图无法区分 | 语义、时间和真实赛道样本；现有几何检查没有解决所有物体图案 |

保留已通过的 63 帧取证回归和当前控制策略，先完成现场静态复测，再根据真实岔路资料调整。不会为了让合成案例都通过而放宽阈值、取消停车保护或沿用失效牌框。

审计输出位于本地 `<实验资料目录>/race_update_20261020/boundary`。`boundary-audit.json` 提供逐例输入、预设场景、分叉行数和结果；本地 `boundary-report.html` 可查看全部 33 张图。

## 离线日志分析

`tools/race_log_report.py` 使用 Python 标准库，读取一个实验文件夹中的：

- `race.csv`：必需。比赛状态、原因、AI 序列、观测年龄、计算命令速度。
- `detections.jsonl`：AI 独立结果；按 AI 自己的图像帧号关联，避免重复使用同一结果造成统计膨胀。
- `control.csv`：巡线有效性、路径问题、控制循环耗时和观测帧率。
- `timing.csv`：采集、预处理、巡线、控制和日志发布阶段的耗时分布。
- `race-config.json` 和 `fork-trace-*/trace.json`：该轮阈值和自动取证索引。

生成 `report.html`、`summary.json` 和 `state-segments.csv`。原日志只读；缺失文件、残缺记录、重复序列会列入警告。

Windows 可以使用现有 Codex Python，不安装组件：

```powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" `
  ".\tools\race_log_report.py" `
  ".\experiment-logs\run" `
  --output ".\analysis-output"
```

也提供 `tools/analyze_race_logs.ps1`，参数为 `-RunDirectory`、可选 `-OutputDirectory` 和 `-Annotations`。

本轮日志有 1916 帧、15 次进入 `FORK_WAIT`，其中 9 次被自动取证保存。1858 个不同 AI 结果中有 1662 个未留下达到阈值的有效目标；这不能直接计为漏检。该轮观测年龄中位数约 72.7 毫秒、P95 约 80.5 毫秒，包含采集和调度，并不是纯 NPU 推理耗时。

默认没有人工标注时，真实误判帧数显示“未提供人工标注”。可根据 `tools/race_annotations_example.csv` 格式填写实际核对过的范围，传入 `--annotations`：

- `expected_label` 按 AI 原始图像帧号匹配，空值表示不评估标签，`none` 表示确认无目标；不能把缺少日志的帧补成空结果。
- `road_layout=straight` 表示已确认是普通直道，才将对应 `FORK_WAIT` 帧计为已确认误判；报告同时列出尚未标注的等待帧。
- 标注区间不能重叠。示例是格式演示，不是昨天实验的事实标注，不能直接套用来计算准确率。

`command_speed` 是程序计算值。即使记录为零，也不能单独证明实际电机已经停住；`--no-control` 测试也会产生这些计算值。

## 静态启动脚本

将 `tools/run_race_static_test.sh` 和昨天的独立 `trackview_race_topology` 放在自己的 `/root/track-trial-20261010/bin`，与原有 `trackview.json`、`race.json` 在一起。保留原程序和配置；本次不需要替换 JSON。

```bash
cd /root/track-trial-20261010/bin
chmod +x ./trackview_race_topology
bash ./run_race_static_test.sh baseline
```

脚本只接受 `baseline`、`signal`、`limit` 三种模式，固定传入 `--no-control`，拒绝额外参数。自动生成单独的测试配置副本和启动记录，记录程序与配置哈希，原 JSON 保持原样。需要现有 `python3` 和已开启的 `diagnostics`，缺失时退出，不自动安装软件。

每次启动后点击图像窗口、按一次 `a` 开始决策；按 Esc 退出，再切换下一模式。

| 模式与命令 | 操作 | 预期反馈 |
| --- | --- | --- |
| `bash ./run_race_static_test.sh baseline` | 无牌观察 10 秒；限速牌、撤牌、解除牌、撤牌各约 5 秒，重复两轮 | 普通直道不再误报 `FORK_WAIT`；关注 `track_view` 巡线是否有效 |
| `bash ./run_race_static_test.sh signal` | 红色停车牌保持约 2 秒，撤牌，随后绿色通行牌保持约 2 秒 | `SIGNAL_WAIT`，撤红牌仍等待；确认通行牌并达到保持时间后恢复 `LANE`。该测试配置临时关闭先过斑马线要求 |
| `bash ./run_race_static_test.sh limit` | 限速牌约 2 秒，撤牌约 2 秒，解除牌约 2 秒 | `LIMIT_ZONE`，撤牌仍限速，解除后 `LANE`。副本中限速为 0.15 m/s，仅验证计算决策 |

记录终端 `[Log]` 的目录名，退出后下载整轮文件夹分析。脚本的 `static-test-records` 保存启动命令及配置副本；自动取证仍在程序打印的日志目录内。

真正岔路的选路、移动中的刹车距离、擦边和 T710 实机耗时尚需现场验证。当前没有实际岔路赛道，不能把本轮静态测试当作比赛行驶验收。
